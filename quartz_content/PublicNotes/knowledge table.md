- Naming conventions
	- (category) big topic with all relevant sub-categories, e.g. [[Code]]
		- can contain information about the whole category generally
	- f (flow) system/blueprint to create something, e.g. [[fCode]]
		- similar to Standard Operating Procedures (SOPs)
			- kind of like a to-do lists to maintain a high standard of quality on a project
	- n (now) - temporary notes to process, e.g. [[nCode]]
		- Like an inbox of ideas I try to empty every time I start to study the category again
	- l (learn) - mentors/resources/archived best content, e.g. [[lCode]]
		- mostly used as a start to better explore the category itself
		- can contain broad sub-topics of the category that I might want to explore in the future
		- some mentors might still be in the RSS reader, the most important ones should be here
	- i (inspiration) - inspiring resources/ideas, e.g. [[iCode]]
	- g (principles) ideas to apply in other area of my life - e.g. [[gDE]]
	- p (project management) - categorized collection of projs
		- These projs can contain their own...
			- milestones, todos, inspiration for new todos, etc
			- a note for the WIP stuff (like commits) that starts with "d" like [[dPW]]
	- m (milestones) - goals to orientate, like [[myMilestones]] but for X
